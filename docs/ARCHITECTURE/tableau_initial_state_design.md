# Tableau Initial State 设计原理

## 背景

在 LTLf synthesis 中，initial_state 的作用是**获取边/ap（assignment pattern）**，用于初始化游戏图。

## 两种获取边的方式

### 方式一：对所有原子变量赋值（简单但有缺陷）

```cpp
// 对每个原子变量 p1, p2, ... 赋值 true/false
for (auto& var : atomic_variables) {
    assignment[var] = true/false;
}
```

**问题**：无法正确处理 Next 公式
- 当前步的 `p1` 赋值 ≠ `X(p1)` 中的 `p1` 赋值
- `X(p1)` 里面的 `p1` 是**下一轮转移**中的 `p1`

### 方式二：对 XNF 公式按与和或拆分（推荐）

```cpp
// XNF 公式中的每个分量都可以看作"变量"
// 例如：X(p1) & p2 可以拆分为 {X(p1), p2}
for (auto& component : xnf_components) {
    // X(p1) 可以直接看作一个变量进行赋值
    // p1 也可以看作一个变量进行赋值
}
```

**优势**：
- `X(p1)` 直接作为"变量"赋值，不需要知道 p1 在下一轮的值
- `p1` 和 `X(p1)` 之间没有约束关系，可以独立赋值

**约束关系的处理**：
- `X(p1)` 和 `X(!p1)` 之间可能有关系
- 但可以**先忽略**，在下一步展开后矛盾会被发现

## XNF（X-Normal Form）

XNF 是指否定只作用于原子命题的范式：
- `!p1` → 已经是 XNF
- `!(p1 & p2)` → NNF 后是 `!p1 | !p2`，这也是 XNF
- `!X(p1)` → 应该转换为 `X(!p1)`

## 当前实现的问题

1. **initial_state 展开**：当前实现递归展开所有子公式（除了 Not）
   - 对于 `!p1`：只包含 `{!p1}` ✓
   - 对于 `X(p1)`：只包含 `{X(p1)}` ✓
   - 但对于复杂公式可能不完整

2. **next 函数**：当前实现基于 assignment 消除文字
   - 对于非时序公式，返回空状态（terminal）
   - 对于时序公式，继续展开

## 建议的改进方向

1. **确保公式转换为 XNF**：
   - `!X(p1)` → `X(!p1)`
   - `!(p1 & p2)` → `!p1 | !p2`（NNF 转换）

2. **获取边的方式**：
   - 对 XNF 公式按与和或拆分
   - 把每个分量（包括 X(xxx)）看作"变量"
   - 先忽略约束关系

3. **Next 的处理**：
   - `X(p1)` 在当前状态是一个"变量"
   - 下一轮展开时，`X(p1)` → `p1`
   - 约束关系在那时会被检查

## 关键洞察

> "p1 和 X(p1) 之间其实没啥约束关系，只不过 X(p1) 和 X(!p1) 之间可能是有关系的，但它们在最终的下一步展开之后，矛盾就会被发现了。"

这意味着我们可以：
1. 把 XNF 的每个分量独立处理
2. 不需要预先解决所有约束
3. 让矛盾在后续展开时自然暴露
