# ADR-002: 为什么选择 Tableau 而非外部工具?

## 状态
有效

## 上下文
LTLf → DFA 转换有两种方案：
1. 使用现成工具 (Lydia/AALTA)
2. 自研 Tableau 构造算法

## 决策
**自研 Tableau 构造**，基于状态集合的显式 DFA。

## 理由

| 方面 | 外部工具 (Lydia/AALTA) | 自研 Tableau |
|------|----------------------|--------------|
| 依赖 | 外部二进制/库 | 无额外依赖 |
| 集成 | 子进程调用/解析输出 | 原生 C++ API |
| 调试 | 黑盒 | 可完全控制 |
| On-the-Fly | 困难 | 易于实现 |
| 性能 | 高度优化 | 基础版 |
| 学习 | 直接使用 | 需要理解算法 |

**关键原因**:
1. **学习目标**: 理解 LTLf Synthesis 核心算法
2. **On-the-Fly**: 自研版本更容易实现懒构造和早终止
3. **调试**: 完全可控，便于理解和调试
4. **独立性**: 不依赖外部工具安装

## 替代方案

### 方案 A: 调用 AALTA

```cpp
// 伪代码
std::string dfa_dot = exec_command("aalta '" + formula + "'");
DFA dfa = parse_dot(dfa_dot);
```

**优点**:
- 成熟稳定，性能高
- 直接可用

**缺点**:
- 需要安装 AALTA
- 子进程调用开销
- 输出格式解析脆弱
- 难以实现 On-the-Fly

### 方案 B: 集成 Lydia 库

**优点**:
- 性能最佳
- BDD 符号化

**缺点**:
- 依赖复杂
- API 学习曲线
- 难以定制

## 后果

**正面**:
- 完全控制 DFA 构造过程
- 易于实现 On-the-Fly 优化
- 无外部依赖
- 便于教学和理解

**负面**:
- 性能不如成熟工具
- 需要自己维护和优化

**风险**:
- 算法实现可能有 Bug
- 大规模公式可能性能不足

**缓解**:
- 充分测试 (10000+ 随机公式)
- 保留与 AALTA 对比的测试集
